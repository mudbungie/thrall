The pipeline stays disarmed (bl-bbb3 open, and its refusal job still stands where its build gate goes), so this is the same act 0.0.1 was: a token publish from a clean `main`, with the bl-006e checklist run in full first. What the flag flip bought was a smaller irreversibility, not none — a yanked version stays downloadable — so the checklist is re-run, not remembered.

0.0.2 carries PROTOCOL 2 (bl-36f7, the worktree lane foot half: a per-tool `subject_cwd` consent in the operator document and an invocation carrying the conversation working directory) and four fixes: a backgrounded helper no longer wedges the channel by holding the pipe past its own deadline (bl-6c14), a capture larger than the wire frame is answered instead of killing the foot (bl-6028), `cwd` is read rather than ignored (bl-3c93), and two refusals stop reading as a library diagnostic (bl-52ba). Plus the session-artifact rule the standing ruling needed (bl-d747).

What is re-run, and why each: the checklist items the tree movement invalidates.

- **The index scan**, over the tree actually being packaged.
- **Each commit added since the publish**, at `--commit` scope — the only scope that reads a commit message, which lands in no file.
- **Refs on the remote**: the trunk and the task store, and nothing else may have appeared.
- **Repository text nobody committed**: pull requests, issues, releases, workflow runs. Any of them is a surface the gate has never seen.
- **`cargo package --list`, audited by hand.** `src/packaged_tests.rs` judges file CLASSES on every gate run and never content, so the audit is not the guard and the guard is not the audit.

Not in scope: arming the pipeline (bl-bbb3 stays), pushing an image (no registry push exists), and any `latest` tag.
