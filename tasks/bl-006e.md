Two operator decisions the founding deliberately did not make. Both are irreversible in the direction that matters, which is why neither is a default.

**1. The remote.** The repository is local and has no `origin`. The task store was founded **stealth** — `task-remote` is the "no remote, on purpose" sentinel — so no op founds, pushes or discovers anything. Setting one is `bl conf set task-remote <url>`, which clears the sentinel.

Before a first push, the publication checklist applies in full and none of it is a gate:

- **History.** A commit hook has only ever seen the tip. Every reachable commit must be swept before the first public push, and a hit means a rewrite *and* rotation of whatever it named — the commit is public the moment the repository is.
- **A rewrite of an existing hosted repository does not clean it.** Pull-request head refs are kept forever and objects orphaned by a force-push stay fetchable by sha. The only publication that can be certified is into a **fresh object store**.
- **Refs other than the trunk.** The task store branch publishes with the source; it is a ref, not a private sidecar.
- **Repository text nobody committed**: pull-request and issue text, review comments, release notes, registry description and metadata.
- **Actions logs and artifacts** survive their run.

**2. The first publish.** `Cargo.toml` carries `publish = false`. The registry name is held by a placeholder at 0.0.0 and must not be touched.

Publishing is irreversible: a yanked version stays downloadable. Before the flag flips, `Cargo.toml` needs an `include` **allowlist** — never an `exclude`, because the failure modes are not symmetric: a missing `include` entry costs a build, which is loud and reversible, while a missing `exclude` entry costs a publication that cannot be recalled. A guard test should read the real packaged file list and fail on anything outside the named classes, in both directions. Auditing the list itself stays a human act: a guard judges file classes, never content.

What this ball named as prerequisite is now built and tested:

- **the `include` allowlist**, three anchored patterns (`/src/**/*.rs`,
  `/README.md`, `/LICENSE`) and nothing else. Anchored because cargo matches
  gitignore-style, so a bare `README.md` means "at any depth" — upstream shipped
  a fabricated-secret corpus's index that way. Without a list the tree packaged
  WHOLE: the agent guide, the design document, every rule and hook, and
  `scripts/leak-fixtures/` beside the binary.
- **the guard**, `src/packaged_tests.rs`: the real `cargo package --list`,
  judged against restated classes — restated and not read out of the manifest,
  because a check that derived its allowlist from `include` would widen with it
  and stay green through the exact edit it exists to catch. Both directions: no
  strays, the files a registry needs are present, the list is not vacuously
  short, and the classes still see their own violations. It also sweeps for
  compile-time embeds, which is the fail-closed list's one cost paid.
- **the release shape**, `.github/workflows/release-plz.yml`: on disk, and
  disarmed at the trigger (`workflow_dispatch` only) with a first job that
  refuses and prints the arming checklist. That job stands where the build gate
  goes, so the edit that arms the pipeline is the edit that gives it one.
  Trusted publishing is documented where it will be configured — no stored
  registry token, an OIDC claim naming this repository and this FILENAME, and
  no way to create a crate that does not already exist.

**What is left is the decision and four mechanical steps behind it**, in order:
adjudicate; give the repository a CI workflow and make the release job `needs:`
it (it must be a CALLED workflow inside the run — crates.io refuses OIDC tokens
minted under a `workflow_run` trigger, so that gate would publish nothing,
quietly, forever); flip the flag and read the guard's answer; register the
trusted publisher and enable Actions-may-open-PRs; add the push trigger.

Two artifact slots in that workflow are deliberately empty and are not this
ball's: no upload job for the release binary or the aarch64-apple-darwin one,
and no image push.

The remote half's own consequence had been left unrecorded in four doc lines,
which are corrected with this, and the check it makes possible — a scan of what
is actually published, the only one an author cannot switch off — is now filed
as bl-e95a rather than standing as a wait for a remote that already exists.

  evidence in bl-d2be's body. Headline: every reachable commit of the trunk and

  the 0.0.0 placeholder and it was not touched.
- **one finding, and it is not published.** The balls LANDING branch carries a
  `conf set task-remote` commit whose message quotes an SSH remote URL — an
  address shape to the scanner — and whose op trailer names a local account.
  That branch is local-only: the remote serves the trunk and the task store and
  nothing else. Publishing the landing would be a disclosure event; nothing
  does, and this is the record that it must not start.
- `cargo package --list` audited by hand against the allowlist, then the
  uploaded tarball audited again after the fact: 52 entries, every one a
  cargo-minted file, one of the two files a registry renders, or a `.rs` file
  under `src`. Zero strays; the fabricated-secret fixture corpus is absent.
- `publish = false` -> `true`, `repository` added (a version's metadata is
  frozen at publication and `cargo package` was warning that none was named),
  and the manifest's stale pointer to the guard corrected.
- **thrall 0.0.1 is on crates.io**, published by hand with a registry token from
  a clean `main`, serving the manifest's real description, the foot-stating
  README, one binary target, and vcs info naming the exact published trunk
  commit. The 0.0.0 placeholder stands beside it, unyanked and untouched.

The release workflow **stays disarmed** and that is not an omission: its own
refusal job stands where its build gate goes, so arming it is the edit that
gives it one. Three of its five steps are left — a CI workflow the release job
`needs:` as a CALLED workflow, the trusted publisher, the push trigger — and
they are bl-bbb3. Trusted publishing cannot CREATE a crate, so that ball was
BLOCKED on this one rather than skipped by it.

What this ball closes on, and why not more: it named two operator decisions. Both
are made and both are enacted. Everything traceable to them that is still open

the disclosure gate, which the publish widened: a crate on a registry is a third
public surface and the only one where a hit has no remedy at all, since a ref
can be rewritten and a published version cannot.
