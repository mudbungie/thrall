`.github/workflows/release-plz.yml`'s `merge-release-pr` job fetches the
published engine's constant from a HARDCODED path:

    raw "$ENGINE_REPO" "$engine_tag" src/wire/hello.rs "$gate/published"

The engine has since split that file. `src/wire/hello.rs` still exists but now
reads `pub use version::PROTOCOL;` — the declaration moved to
`src/wire/hello/version.rs`. `protocol_of` anchors on
`^\s*(pub(\(..\))?\s+)?const\s+PROTOCOL\s*:\s*u32\s*=\s*(\d+)\s*;`, and a
`pub use` matches nothing, so the fetch succeeds and the read finds no
declaration.

## What that costs

`judge` holds on an unreadable published input, deliberately — "a gate that
could not read its inputs has not answered, and a hold is undone by the next
run while a publish is undone by nothing." That is the right default and it is
the wrong answer here: the input is readable, at another path. So the moment
the engine publishes 18 — the event the current hold is waiting for — this
crate's release does not unblock. It swaps one hold for a permanent one, and
the sentence it prints ("the published engine's PROTOCOL could not be read")
reads as an engine defect rather than a stale path in this file.

Verified locally against the real artefacts: with the engine's `v0.0.52`
`src/wire/hello.rs` (which still declared the constant at that tag) the gate
answers `hold: this release speaks PROTOCOL 18 and the published engine speaks
17`, exit 3 — correct. Against the engine's `main`, that same path declares
nothing.

## The shape of the fix, and what it must not become

The gate is pure logic and reads no network by design; the fetching is the
workflow's. So this is the workflow's defect, not `protocol-gate.sh`'s — but a
hardcoded path in the workflow is a second copy of a fact the engine owns, and
it will rot again the next time the engine reorganises a module.

A path LIST is the obvious repair and is the thing to argue with: it is
config, it grows on every engine refactor, and a gate that tries several places
and takes the first hit can be satisfied by a file that is no longer the
authority. Worth weighing against a fetch that asks the engine where its
constant is — its published crate, or its `corpus/` (which the wire's own
shapes already ride in, and which this crate already reads by hand at every
re-vendor).

Whatever is chosen, the failure must stay fail-closed and its sentence must
name THIS repository's stale expectation rather than the engine's file.
