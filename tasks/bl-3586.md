Operator ruling (yog bl-223f, 2026-08-30): every component ships a container
image for DEPLOYMENT SANITY, not for internal container semantics. Nothing
inside thrall uses the container filesystem as a feature; the image is the unit
of install and nothing more.

Deliver, in this repo:

- `Containerfile`, multi-stage. Build under the pinned toolchain
  (`rust-toolchain.toml`, 1.95.0) so the image is reproducible from the same pin
  the gate uses. Runtime stage carries exactly what the binary execs and no
  more.
- `make image`, autodetecting podman or docker, tagging from the crate version.
  It PUSHES NOTHING — the registry is an unanswered question and pushing waits
  on the coordinated publish moment.
- README section: what mounts where (the XDG data root is the runtime contract,
  and the image carries no state), and what the image deliberately does not
  contain.

The runtime-layer choice is thrall's to make and to RECORD. A foot execs
operator-configured argv: what it runs is not knowable from this repo, so a
`scratch` runtime — correct for a binary that execs nothing — would ship a foot
that can only fail. State the base, state why, and state that the operator who
enables a tool owns whether the layer can run it.

The image carries no `tools.json` and no `wire/workspaces/`. Both are
operator-provisioned by hand, thrall never writes either, and a certificate
baked into a layer is a certificate published to everyone who can pull it.

Proof, not assertion: the built image answers `--version`, and `thrall run` on
an image with an empty data root refuses naming the missing tool document —
this repo's documented behaviour, exercised through the image.
