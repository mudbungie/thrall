thrall's task store is a git branch that publishes with the source. Ball bodies are published text and the source gate never sees a byte of them. thrall was founded without a scanner, so it is not opted in to the machine-level store gate — which keys opt-in on the project shipping an executable `scripts/leak-scan.sh` and silently passes a project that does not.

Deliverable: the scanner, its rule table, its fixtures, and the two wirings.

- `scripts/leak-rules.sh` — the one definition of what may not be committed: private keys, vendor tokens, credential assignments, routable addresses, absolute paths under any home root, addresses outside the reserved documentation space, dialogue behind a speaker label, agent-session artifacts, and **content no rule can read** (unreadable is rejected, not skipped — the binary class is the one most likely to carry a dump).
- `scripts/leak-scan.sh` — the mechanism. It reads **index blobs**, not the worktree, so the bytes scanned are the bytes committed. Findings are truncated: a finding must LOCATE a leak, never reprint it into a terminal or a log.
- **Two scopes.** Bare scans the whole tracked tree — the right question for a commit hook. `--commit REV` scans what one commit publishes, plus its message, which is the store gate's question and the only scope that can read a `-m` note. A tree scan over a shared long-lived store checkout wedges every author on every other author's text.
- **Both directions, always.** Every rule owns a fixture where every non-comment line must be flagged by that rule, plus near-misses that must not be. A leak gate dies by matching nothing; a noisy one dies by being bypassed.
- Wire it into `make lint` **before** the verdict cache, into `.githooks/commit-msg` (which sees the message no pre-commit hook ever does), and into the store's `<op>.post` schedule immediately ahead of the publisher.

Prevention is local and bypassable; enforcement is remote and late. Say so rather than shipping a gate that implies otherwise.
