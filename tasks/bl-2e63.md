The gate now runs on a shared runner (bl-bbb3 armed CI), and this is the one
test in the suite whose verdict is a wall-clock race rather than a property.

`src/exec/tests/bounds.rs`, `a_tool_that_leaves_a_helper_holding_the_pipes_still_answers`
runs the executor on another thread and gives the whole capture two seconds:

    let got = rx.recv_timeout(Duration::from_secs(2))
        .expect("the capture, long before the helper lets the pipes go");

The tool is `sleep 5 & printf started`, so the number that matters is the gap
between the child exiting and the helper releasing the pipes five seconds
later. Two seconds sits inside that gap with no margin stated, and the test is
run under tarpaulin, whose ptrace instrumentation multiplies every syscall on
the path.

OBSERVED, twice in a row, on a box at load average 9: `Timeout`, one test
failing out of 163, with a `make check` minutes earlier on the same tree green.
So it is not a regression and not this tree — it is a budget that holds on an
idle machine and not on a busy one. A GitHub runner is two vCPUs and is always
the busy case.

WHY IT IS WORTH A BALL NOW rather than a retry. Until CI existed this cost an
agent one re-run. It now sits on the release path: the gate is `needs: ci`, so
a spurious red does not merely annoy, it withholds a publish, and a flake on a
publishing gate is the kind that gets a gate disabled rather than fixed.

WHAT NOT TO DO: raise the constant and leave it a race. The assertion worth
making is that the capture does not wait on the HELPER, and a race against a
fixed duration is an indirect way of asking that. Either bound the wait by
something derived from the deadline the executor was handed, or make the
helper deterministic — a signal the test releases rather than a sleep it
outlasts, so the test asserts an ordering instead of outrunning a clock.

Delivered by bl-2532 (ca636db's parent 2de387f): the helper now holds the pipes for 30s against a 10s deadline handed to the run, with the stock deadline as the outer recv bound, so waiting on the stranger earns a deterministic TIMED_OUT capture instead of a race. Measured before the fix on a loaded box: 1503ms / 2018ms / 2112ms against the 2s wall, 0.07s run alone.
