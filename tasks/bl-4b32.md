RECOMMENDATION: refuse the foot half. Premises checked against all three trees — litany's landed bl-b66b (src/prompt/dispatch/tool_step/context.rs, src/workspace/cwd.rs, src/prompt/tool/inject.rs), yog's worktree lane (src/tool_host/subject.rs, src/registry/mailbox.rs), thrall's executor (DESIGN 3.4/3.5, src/exec.rs). Three findings, in the order they bite.

1. The gap this ball posits does not exist in the one lane whose cwd is the agent's. litany resolves the agent's working directory through workspace::cwd::effective, which takes the cd mark only when it is_dir() on the ENGINE's box and otherwise falls back to the agent's worktree. So an agent's effective cwd is by construction a live directory the engine can read, and the engine's append is never empty for want of a path it cannot reach. The routed worktree lane carries exactly that path — litany RoutedCall::cwd, yog's routed leg, the invocation's optional cwd — and only to an entry the operator marked subject_cwd, which REMOTE 5.4 puts on the co-located foot precisely because that box is the one holding the worktrees. The engine reads the agent's own tree; the foot executes in it.

2. In every other lane the foot's directory is not the agent's cwd, so its context files are not the agent's context. A loaded host-qualified entry runs at the operator's own cwd on that box (thrall DESIGN 3.4, 3.5), and an invocation carrying a directory against an unconsenting entry is refused in band naming the key. Files up that path are a different tree's instructions to a different worker. Appending them would frame them as this agent's — and because "shown" is derived per framed path and nothing unmarks it, the agent would be told once and permanently about a directory it cannot cd into at all, since cd resolves on the engine's box and the mark can therefore never name a foot-only path.

3. The price, which is what settles this rather than leaving it a maybe. Neither surface can carry the bytes today. RoutedCapture is exactly three facts and its own contract states that a routed tool is indistinguishable from a local one to the model by construction rather than by convention; a fourth fact is a litany seam amendment, then a yog REMOTE PROTOCOL bump for the capture shape, and only then a thrall change — and thrall does not get a vote on the wire. And the foot holds no transcript, so the honest implementation posts every context file it finds on EVERY capture and lets the engine dedupe: full bytes on every tool call, for an append that fires at most once per path per agent.

WHAT WOULD REOPEN IT, so this is a decision and not a dismissal: a deployment where the agent's worktree is not on the engine's box. Then effective()'s worktree fallback names a path the ENGINE cannot read either, the gap belongs to the engine as much as to the foot, and the answer is a ruling about where a worktree lives (REMOTE 5.4) rather than a field on a capture. Nothing in the three trees today produces that deployment.

Left open rather than closed because the refusal contradicts a standing sentence in another repo: litany docs/DESIGN_CONTEXT_ECONOMY.md 6 ("Where it cannot reach") says that foot may carry its own discovery. Retiring this ball is that edit plus this one, which is a cross-repo ruling and not thrall work.

RULING: refused, the foot half is not built. The administrator adopts the recommendation above: an agent's effective cwd is by construction a directory the ENGINE can read (litany workspace::cwd::effective takes the cd mark only when it is_dir() on the engine's box and otherwise falls back to the agent's worktree), so no lane leaves the engine's context-file append empty for want of a path it cannot reach, and a foot-side discovery would post a different tree's instructions as this agent's — permanently, since 'shown' is derived per framed path and nothing unmarks it. The doc that carries this ruling is litany bl-d1b1, which replaces DESIGN_CONTEXT_ECONOMY.md §6's 'that foot may carry its own discovery' clause with the invariant, the reasoning, and the one condition that would reopen it (an agent worktree that is not on the engine's box). thrall keeps RoutedCapture at three facts; no wire shape moves and no code changes here.
