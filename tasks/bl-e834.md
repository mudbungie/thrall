Found while verifying bl-2d78, and filed separately because it is about
*reporting*, not about the advertised set.

## What happens

`run::fan` spawns one thread per entry and then joins them in filing order,
collecting each channel's closing sentence into a `Vec<String>`. `serve::serve`
joins that vector with newlines into one `Verdict::failed`. So **nothing is
said until every channel has stopped.**

On a box holding one entry — the common case — the process exits the moment its
channel dies and the sentence is the exit. On a box holding two or more, the
first death is buffered for as long as any sibling is still serving, which for
a healthy sibling is forever. The operator's symptom is a live-looking process
that is serving one engine and silently not serving another.

## Why it matters more than it did

DESIGN §2 is explicit that thrall never reconnects, so **the sentence is the
product**: a supervisor's log is the whole of what an operator gets on this
path. A sentence that is written but not emitted until an unrelated thread
stops is a product that does not ship.

It also blunts the two refusals yog bl-1462 added, which are the engine telling
this box that something else is presenting its certificate — the loudest thing
the far end can say, arriving at a process that will not repeat it.

## The shape of the fix, and what it must not be

Say each channel's sentence when that channel stops, and keep the collected
vector as the exit's summary. The seam is `run::fan`'s per-thread arm, which is
the one place that already knows both the entry's name and its sentence.

It must not become a logging layer: one stream, one line per dead channel, no
levels, no filtering, no timestamps thrall invents (the supervisor stamps its
own). It must not change the exit code or the verdict text, both of which are
`cli`'s and are tested as values — the emission is beside the verdict, not
instead of it. And it must stay off the pure-function path: `cli::run` decides
and says nothing, which is what lets `src/main.rs` be the one file outside the
coverage floor.

Narrowed by bl-916d, not resolved. Every RETRYABLE ending now reaches the operator as it happens: run::redial says the sentence that ended the connection plus the wait before the next dial, through the run::Notice sink, under the channel's own name — the same sink the disarm notice uses. What is still buffered is the TERMINAL sentence, the ending another dial cannot improve, which run::fan still collects and answers only once every channel has stopped. So the complaint's shape is unchanged for a multi-entry box whose one channel ends over while the others keep serving; the redial removed the far more common case from it.
