Round-1 install lane of the suite usability campaign (yog docs/STORIES.md S0/S9).

## The gap

`README.md`'s top-level sections are: Why it is a separate program, Foot-grade
trust, Status, Build, The image, The macOS artifact, The rules, Authorities,
License. There is no Install section, and the string `cargo install` does not
appear in the file.

"Build" is addressed to a contributor. "The image" is a complete, well-written
install route for a box that takes images. The crate route — which is how the
other three components are installed, and how the campaign's clean-room run
installed this one — is not mentioned, even though the README elsewhere states
at length that the crate IS published:

> thrall is published to crates.io. It was not, for as long as the decision of
> whether, when and as what it first ships was open …

## The route works, and is the fastest of the five

Bare `ubuntu:24.04`, only `curl git build-essential` and rustup:

    cargo install thrall --locked    10s

(fast because brazen/litany/yog ahead of it had already warmed the shared
registry and the dependency builds). No system dependency beyond the C
toolchain.

## Expected

An Install section naming `cargo install thrall --locked` beside the image
route, and a one-line statement of what the binary needs on the box at runtime
(nothing, beyond whatever the operator's own `tools.json` entries spawn).

## Severity

p3 rather than p2: unlike the server, a foot is an explicitly deliberate
addition and its operator is likelier to have read further. Still the first
thing a stranger looks for.

yog's README has the same gap and is filed on its own board.
