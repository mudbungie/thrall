Operator ruling 2026-08-30: agent-session URLs are BANNED from all published
text in these repositories — ban them, no reason to allow it.

WHAT WAS FOUND, and it was found in the seat rather than here. A vendor
code-session URL sat in the body of a pull request on the seat repository
(lernie bl-9fbe), put there by harness convention. It is permanent: the forge
keeps a body's edit history and serves `refs/pull/<n>/head` forever, so an edit
buys the false assurance a history rewrite buys elsewhere. The remedy for what
is out is nothing; the remedy for the next one is a rule.

THE RULE DOES NOT SEE IT, HERE EITHER. `scripts/leak-rules.sh`'s
`session-artifact` pattern is near-byte-identical across four repositories, and
none of the four names the URL form. Its resource-prefix alternation does not
carry the session prefix, and it has no alternative at all for a URL path
shape.

WHY IT MATTERS THOUGH THE TEXT IS IN NO TREE. The gate is what an author is
judged by at the moment of writing, and the same identifier lands in a commit
message, a ball body and a pull-request body out of one habit. Two of those
three ARE scanned — `commit-msg` runs the scanner over the message and the
store gate runs it over the ball — so the hole is not confined to the place it
was found.

THE FIX. Two alternatives on `session-artifact`, each with its own fixture line
so a dead one cannot hide behind a live one: the bare session id prefix joins
the resource list, and the code-session URL path shape catches an id under that
path whatever its prefix. Fixture lines carry the `notreal` marker; `clean.txt`
gains the near-miss and must keep not firing. Rule text stays byte-identical
with the sibling tables.

THE POLICY HALF. AGENTS.md gains the standing ruling where the published-text
rules live: PR titles and bodies, issue text, review comments and release notes
never carry a session URL or a conversation identifier, and the harness
convention of appending one to a PR body is overridden here. No gate can reach
a PR body; that half is the author's.
