Round-1 install lane of the suite usability campaign (yog docs/STORIES.md S0/S9).

## Scenario step

A stranger enrols the local foot. `README.md` names the file:

> Two files, both put there by the operator's hand and neither ever written by
> thrall: `<data root>/tools.json` and one directory per channel under `<data
> root>/wire/workspaces/`

and, further down, shows what a missing one costs:

> `thrall: /state/thrall/tools.json: No such file or directory (os error 2) — this box has no tool config`

That is the whole of what the README says about the file. It never shows one.

## What it takes to write the first one

Three sources, in two repositories, none of which carries an example:

1. `docs/DESIGN.md` §3.4 — prose: *"The first three keys of each entry **are**
   the advertised element; `command` and the optional `cwd` are the local
   half"*, plus `subject_cwd`, plus the rules (name is a single path component,
   `cwd` must be absolute, `[]` is honoured, an absent file refuses).
2. yog's `docs/REMOTE.md` §5.1 — the only place the three advertised keys are
   ever *named*, in a JSON block for the `advertise` gesture rather than for
   this file:

       {"name": "Bash", "description": "run a command",
        "input_schema": {"type": "object", "properties": {"command": {"type": "string"}}}}

3. `src/exec.rs`'s module comment — the only statement of the tool contract
   itself: *"stdin, bytes on stdout, the exit code the verdict"*. Neither
   README nor DESIGN says how the invocation's input reaches the command. A
   reader who does not open the source will assume argv interpolation, which
   §3.4 explicitly forbids, and write an entry that silently receives nothing.

## Expected

One worked `tools.json` in the README — two entries, one plain and one carrying
`subject_cwd` — and one sentence stating the contract: **the invocation's input
JSON arrives on the command's stdin; its stdout is the capture; its exit code is
the verdict.** That single sentence is the difference between a foot that works
and a foot that advertises a tool which returns nothing, and it is currently
reachable only by reading Rust.

## Severity

p2. `thrall run` is one of the four acts of a single-box install and the file it
demands cannot be written from the shipped documentation. The refusal for a
missing file is exemplary; there is nothing to write into it.
